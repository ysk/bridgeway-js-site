1. 読み込む

demo.html という名前でファイルを1つ作って、これを丸ごと貼ってください。
そのままブラウザで開けば動きます。以降はこのファイルの中身を書き換えていきます。 

<!doctype html>
<html lang="ja">
<head>
<meta charset="utf-8">
<title>demo</title>
</head>
<body>

<p>ここに作っていきます</p>

<script src="https://cdn.jsdelivr.net/npm/bridgey@2"></script>
<script>
  console.log($$.version);   // 2.x が出れば読み込めています
</script>

</body>
</html>

F12 でコンソールを開いておいてください。 bridgey は間違いを黙って無視せず、直し方を添えて教えます。それがこのライブラリの主な機能です。

2. state — 状態を持つ

読み書きの規約は .val() と同じ。引数なしで読み、引数ありで書きます。

<p>数量 <span id="qty"></span></p>
<button id="inc">＋</button>

<script>
  const qty = $$.state(1);

  $$("#qty").text(qty);                  // ← state を渡すと、以後ずっと追従する
  $$("#inc").click(() => qty(n => n + 1));
</script>

$$("#qty").text("1") なら「その瞬間だけ入る」（jQuery と同じ）。 state を渡したときだけ、ずっと追いかけます。増えた概念はこれだけです。

3. computed — 計算する

合計・小計・表示するかどうか。「代入する場所」を作らないのが要点です。

<p>合計 <span id="total"></span> 円</p>

<script>
  const qty   = $$.state(1);
  const total = $$.computed(() => qty() * 1100);

  $$("#total").text(total, $$.money);    // 23,800 のように3桁区切り
</script>

total に代入している行はどこにもありません。だから 「オプションを増やしたのに合計の更新を忘れた」が起きません。 現場で最も多い金額事故がこれです。

表示の形は「値 → 加工 → 形」の順に足せます。

$$("#n").text(qty, "個");                  // 3個
$$("#n").text(qty, "残り{}個");            // 残り3個
$$("#n").text(total, $$.money, "円");      // 23,800円

4. when — 出し入れする

<p id="free">3個以上で送料無料</p>

<script>
  $$("#free").when(() => qty() >= 3);
</script>

show() / hide() はありません。表示を状態から導出すると、 初期表示と更新が同じ式になるのでズレません（jQuery で「初期化だけ別に書いてズレる」のが定番事故です）。

見せてはいけないものは when(state, { detach: true }) を使ってください。 CSS で隠す方式は、class 名のタイポや CSS の1行削除で「見えてしまう側」に倒れます。

5. repeat — 一覧を描く

雛形は <template> に置き、中身はいつもの jQuery で書きます。

<ul id="list"></ul>
<template id="row">
  <li><span class="title"></span> <input class="memo" placeholder="メモ"></li>
</template>

<script>
  const todos = $$.state([
    { id: 1, title: "牛乳" },
    { id: 2, title: "卵" },
  ]);

  $$("#list").repeat(todos, {
    key: (t) => t.id,
    tpl: "#row",
    render: ($row, t) => $row.find(".title").text(t.title),
  });

  // 1件足してみる → メモ欄に入力した文字は消えません
  setTimeout(() => todos((list) => [...list, { id: 3, title: "パン" }]), 3000);
</script>

メモ欄に何か入力してから3秒待ってください。行が増えても入力した文字は残ります。 $("#list").html(…) で作り直す従来の方法だと、入力もフォーカスもスクロール位置も飛びます。

<table> の <tr> や <select> の <option> でも使えます。 サーバーが出力済みの一覧を乗っ取るなら { from: "li" }。

6. フォームの事故を止める

HTML は1文字も変えません。既にある required や type="email" を読みます。

<form id="signup">
  <input name="mail" type="email" required>
  <input name="tel" required>
  <div style="display:none">
    <input name="promo" required>   <!-- 画面に出ていない必須項目 -->
  </div>
  <button type="submit">送信</button>
</form>
<p id="err"></p>

<script>
  const f = $$("#signup").form({
    tel: { pattern: /^0\d{9,10}$/, message: "電話番号の形式が違います" },
  });

  $$("#err").text(f.errorCount, "件の未入力");
  f.submit(async (values) => {
    console.log("送信", values);        // 連打しても1回だけ
    await new Promise((r) => setTimeout(r, 800));
  });
</script>

メールと電話を埋めれば送信できます。画面に出ていない promo は検証されません。
標準の HTML5 検証だと、この required で送信がブロックされるのに理由を表示できず、 ユーザーには「押しても何も起きない」としか見えません。そのまま離脱します。

試してみてください。

  • オートフィル: コンソールで document.querySelector('[name=mail]').value = "a@b.com" — イベントを飛ばしていないのにエラーが消えます
  • 日本語入力: 電話欄で漢字変換してみてください。変換中に赤くなりません
  • 連打: 送信ボタンを連打しても、送信は1回だけです

7. common.js を安全にする

全ページで読まれるファイルに「手続き」を書くと、要素が無いページでも走り、 1箇所の undefined で以降が全部死にます。「登録」だけを書く形にします。 

<!-- このページで動かしたい部品を HTML 側で宣言する -->
<div data-component="counter" data-start="5">
  <button class="dec">−</button><b class="n"></b><button class="inc">＋</button>
</div>

<script>
  // common.js に書くのはこれだけ（実行はしない）
  $$.component("counter", ($el, props, ctx) => {
    const n = $$.state(props.start ?? 0);
    $el.find(".n").text(n);
    $el.find(".inc").click(() => n((v) => v + 1));
    $el.find(".dec").click(() => n((v) => v - 1));
  });

  // わざと壊れる部品も置いてみる
  $$.component("broken", () => { undefined.foo; });
</script>
<div data-component="broken"></div>

broken は失敗しますが、counter は動き続けます。 コンソールには「失敗した部品名」と「生きている部品名」が出ます。
data-component が無いページでは1行も実行されません。 Ajax で後から追加した要素にも自動で適用され、消えたら自動で片付きます。

8. 既存 jQuery と混ぜる

jQuery を消す必要はありません。同じページ・同じ要素で共存できます（$ は奪いません）。

<script src="https://code.jquery.com/jquery-3.7.1.min.js"></script>
<script src="https://cdn.jsdelivr.net/npm/bridgey@2"></script>
<script>
  // 入力周りは既存の jQuery のまま
  $("#qty").on("change", function () { /* 既存の処理 */ });

  // 金額の計算だけ bridgey に移す
  const qty   = $$("#qty").state(1);
  const total = $$.computed(() => qty() * 1100);
  $$("#total").text(total, $$.money, "円");
</script>

しかも既存 jQuery が $("#qty").val("3") で値を入れても bridgey が追従します （value の代入自体を見ているため）。だから「フォームの検証だけ移す」ができます。

※ jQuery プラグイン（slick / DataTables 等）は bridgey では動きません。jQuery 本体と併用してください。

9. 警告を読む

bridgey の主な仕事は「黙って壊れないこと」です。わざと間違えてみてください。

$$(".typo-selector").text($$.state(1));
// → 0件でした。text() を結びつけられません。HTML が変わった可能性があります…

$$("#box").toggleClass("actve", open);
// → このクラスはどの CSS にも定義されていません。似ている名前: "active"

$$("#list").repeat(items, { key: () => 1, tpl: "#row", render: … });
// → キーが重複しています: 1

$$("#row").next();
// → next() は使えません。構造が変わると壊れるため…
//    → closest("@row").find("@price") のように名前で引いてください

$$("#box").addClass("active");
// → 状態を表しているようです。.selected(state) が使えます（aria-selected も付きます）

本番でうるさければ $$.warn = false（事故の警告）/ $$.hints = false（改善の提案）。
