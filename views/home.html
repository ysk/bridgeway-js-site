なぜ bridgey か

jQuery でよく起きる事故を、止めます。

どれも保守の現場で繰り返し起きている問題への対策です。

数値計算が合わない

change の中で合計を計算して代入していた。初期表示で走らない／別の箇所で上書き／動的に足した項目に効かない。
→ 合計は導出値。代入する場所が存在しないので、更新漏れが起きません。

非表示の必須項目で送信できない

画面に出ていない required で送信がブロックされ、理由も表示されない。ユーザーは離脱し、CVが消える。
→ 見えているフィールドだけを検証します。

オートフィルで入力しても未入力扱い

自動入力や JS 代入では input が飛ばないので、検証が走らない。埋まっているのに送信できない。
→ 値の代入自体を検知します（既存 jQuery の .val() 経由でも）。

HTMLを1つ挟むと静かに壊れる

next() children() eq() は構造に依存する。要素を1つラップしただけで、例外も出ないまま動かなくなる。
→ 名前で引きます。0件なら警告します（jQueryは黙ります）。

1つの undefined で全機能が死ぬ

common.js の $(function(){}) の中で1箇所 undefined を踏むと、以降に登録されるタブ・モーダル・アコーディオンが全部死ぬ。
→ 部品単位でエラーを隔離します。壊れたものだけが止まります。

日本語入力で壊れる

変換中に値を書き戻すと、変換候補が消える・確定できない・文字が化ける。電話番号や全角半角の自動整形で必ず起きる。
→ 変換中は値を触りません。海外製ライブラリはここを見ていません。

段階的移行

全部書き直さなくていい。1機能から。

レガシーな技術を止められない現場のために。これが最優先の設計です。

いまのやり方（そのまま動く） 
$(".tab").on("click", function () {
  $(".tab").removeClass("active");
  $(this).addClass("active");
});
bridgey の JS API — 事故が減る（ARIA も自動で付く） 
const current = $$.state("a");
$$(".tab").each((el) => $$(el)
  .click(() => current(el.dataset.tab))
  .selected(() => current() === el.dataset.tab));
そのまま、事故の起きない形に寄せていく 
// 合計は「代入」ではなく「導出」にする → 更新漏れが消える
const total = $$.computed(() => picked().reduce((s, k) => s + PRICE[k], 0));
$$("#total").text(total, $$.money, "円");

// 一覧は repeat に任せる → 入力途中もフォーカスも飛ばない
$$("#list").repeat(items, { key: (i) => i.id, tpl: "#row", render: … });

// common.js は「登録」だけにする → 1つ壊れても他は動く
$$.component("tabs", ($el) => { … });

①で止めてもいい。②で止めてもいい。止めたところまでの分だけ、事故が減っています。
新しいフレームワークを入れる稟議も、ビルド環境の用意も、要りません。

インストール

<script> 1行から。

今すぐ試すなら CDN。型が欲しくなったら npm。どちらでも機能は同じです。

<script> 1行（ビルド不要）
<p>合計 <span id="total">0</span> 円</p>
<button id="add">追加する</button>

<script src="https://cdn.jsdelivr.net/npm/bridgey@2"></script>
<script>
  const count = $$.state(0);
  const total = $$.computed(() => count() * 1100);

  $$("#total").text(total, $$.money);
  $$("#add").click(() => count(n => n + 1));
</script>

$ を $$ にするだけ。増えた概念は1つだけです: 値を渡すと1回きり、state を渡すとずっと追いかける。

npm（型が付きます）
npm install bridgey
import { $$ } from "bridgey";
import { $$ as $ } from "bridgey";  // 好きな名前に

TypeScript で書かれているので、型定義が実装とズレません。
<script> で読むときは、名前を1箇所で変えられます。 

<script src="…/bridgey@2"></script>                       // $$（既定）
<script src="…/bridgey@2" data-global="$"></script>      // $ で呼べる
<script src="…/bridgey@2" data-global="brg"></script>    // brg で呼べる
<script src="…/bridgey@2" data-global="brg,$$"></script> // 両方の名前で呼べる

jQuery 互換

保守の手を止めず、
より安全な書き方へ。

既存コードをコピペしても1行目で落ちません。後方互換が無いと、レガシー現場では導入すらできないからです。
そのうえで事故になりやすい書き方には、開発時に1回だけヒントが出ます（$$.hints = false で止まります）。

そのまま動くものヒントで案内する、より安全な書き方
next / prev / siblings / eq / indexclosest("@row").find("@price")（構造ではなく名前で引く）
show / hide / togglewhen(state)（表示を状態から導出する）
fadeIn / fadeOut / slideToggleCSS の transition ＋ .toggleClass("is-open", state)
$$.ajax / $$.get / $$.post$$.resource()（後着追い越しを防ぐ）／$$.action()（二重送信を防ぐ）
$$.each / $$.map / $$.extend / $$.trimヒントなし（危険ではないので、そのまま使ってください）
serialize / serializeArrayヒントなし（検証は form() が担当します）
prepend / before / after / clone / wrap / detachヒントなし（一覧は repeat() の方が安全です）
width / height / offset / position / scrollTopヒントなし
one / trigger / hover / readyヒントなし

入れないもの: ルーター / SPA 化（URL の主権はサーバーに）・スコープ付き CSS・仮想DOM・SSR。
jQuery プラグイン（slick / DataTables 等）は bridgey では動きません。jQuery 本体と併用してください（$ は奪いません）。
